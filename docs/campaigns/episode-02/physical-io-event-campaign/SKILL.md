# Physical I/O event campaign

Use when planning a new Physical I/O event or continuing its campaign. First read [the recurring checklist](references/campaign-checklist.md). Ask for only missing facts that affect delivery; continue independent drafting while answers are pending.

Create or update an event folder with confirmed brief, dated calendar, copy/creative pack, asset ledger, distribution/sponsor list and process/results log. Reuse current files rather than duplicating a campaign. Determine the event year/timezone and verify any supplied booking page belongs to this event.

Physical I/O’s voice is curious, concrete and multidisciplinary: design, engineering and intelligent systems in the physical world. The recurring editorial device is a cinematic anthology: a new central question, consistent brand motion, human POVs and a bridge from the last event. Episode 02 used Love, Mind + Body; choose a fresh theme when appropriate, not a mandatory theme for all events.

Distinguish footage, host scripts and proposed narration. Watch/transcribe recordings before claiming quotes or assigning exact cuts. Preserve whether the previous event was online or in person. Never repurpose conceptual visuals as documentary proof. Historical affiliations, audience numbers and hiring roles need fresh verification.

Anchor the calendar to the actual event date and available lead time. Give each item an owner or Unassigned, dependency and truthful status. Keep optional sponsor/hiring/podcast posts conditional on real agreements, roles and assets. Record blocking inputs without pretending production or publication is complete.

Prepare external messages and posts as drafts unless the user has explicitly authorised sending/publishing. Preserve any existing recipient consent and admin workflows. No campaign plan alone authorises outreach or starts a recurring scheduler. Log external actions only after confirmed success.

At close, record outcomes and revise reusable guidance from observed lessons. Report what exists, what was actually executed and what remains dependent on people/assets. This skill is an on-demand workflow, not an unattended publishing automation.

## Storyboard endpoint rule (user revision, 14 September 2026)
In storyboard mode, always show a labelled first frame and end frame for every shot. Generate missing endpoint images before animating. Keep the camera fully locked: no pan, tilt, dolly, zoom, drift, reframing or focus pull. Preserve lens, crop, perspective, hardware, light and texture between endpoints. Animate only the intended mechanical state change. For flip-dot scenes, create the all-black first frame by editing the end-frame image. Pass the first image and last_frame constraint to Veo. Build shot 06's final legible mechanical date board before generating its motion. Review endpoint fidelity and fixed hardware throughout the result.
