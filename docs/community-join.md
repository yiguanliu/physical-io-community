# Community join

The public /join route asks the supplied 11 questions one at a time, followed by review and consent. Timestamp is generated by Postgres. Optional portfolio / LinkedIn / suggestions can be skipped. No admin or login privileges are created.

Server POST /api/join validates the payload and origin, uses a shared database rate limit, and atomically writes a member, interests, subscription preferences, audit event and two private notification jobs. Existing email addresses receive a generic success; their records, consent and notifications are unchanged. This is membership registration, not verified email ownership.

Notifications go only to soul@physical-io.com and anthony@physical-io.com. The initial delivery runs after signup; /api/join/notifications retries pending jobs using CRON_SECRET. Failed email delivery does not roll back membership. Resend idempotency keys prevent immediate duplicate retries; jobs older than 23 hours move to review rather than risk duplicate delivery. Check private.join_notifications for pending/review rows. Vercel runs a daily recovery sweep at 08:00 UTC on the current Hobby plan; new signups also trigger pending deliveries. Immediate notifications are not delayed by this schedule. Configure the same schedule in your hosting platform if hosted elsewhere.

Required server configuration: DATABASE_URL, RESEND_API_KEY, verified RESEND_FROM, NEXT_PUBLIC_SITE_URL, CRON_SECRET. Secrets must stay server-side and must also be set on deployment. Apply supabase/migrations/20260907021319_community_join.sql before using the route in another environment. Public clients have no access to the private notification/rate-limit tables.

Verified locally: TypeScript, validation/duplicate/retry tests, and a real Supabase signup transaction that was rolled back, including interest mapping, both notification recipients and absence of marketing consent by default. Resend API key and domain verified read-only. No test notification was sent.

Run node --import tsx --test lib/join/join.test.ts. The explicitly invoked lib/join/verify.integration.ts uses configured Supabase with a rollback; do not run it as a general production health check.
